# 画面・UX・コンポーネント仕様

**版** 1.1 / **改訂日** 2026-11-08 / **要求参照** FR-02〜08, NFR-02, PR-01

## 1. 全体方針
- PC・スマホ両対応のレスポンシブ。学習ルームはキャラクター＋チャット型（B案）で確定（ADR-017）。
- ユーザーは「学習内容選択→教える→ぴあ友からの質問→問題を出す→検証→レポート」を、少ない画面遷移で終えられる。
- 学校の正式な評価と混同させない。点数は**ぴあとも独自の説明力スコア**と明記する。
- 外見の比較ではなく、ぴあ友が「できるようになったこと」「習得した概念」を成長の主役にする。
- ぴあ友の習得は、用語集の4つの言葉（未習・説明済み・練習中・習得済み）とアイコンで表す。別の言い方はしない。
- 画面の言葉も「授業」「ぴあ友」を使う。「講義」「生徒」とは書かない（ADR-034）。
- 見た目はチームのデザイン（v7、12の表）に合わせる。色や形の決まりは1.3。

### 1.1 PCとスマホの切り替え
- 画面の幅が**1024px以上ならPCの配置**、それより狭ければ**スマホの配置**にする（Tailwindの`lg`）。
- PCとスマホで、出す情報と操作は同じにする。違うのは配置だけ。片方にしかない要素は、各画面の表に「なし」と書く。
- 各画面の配置は、画面ごとの「PCとスマホの配置」の表に従う。

### 1.2 画面の移動（共通ナビ）
| | PC | スマホ |
|---|---|---|
| 置き方 | 画面上部のナビバー。左にロゴ、中央に4つのリンク、右にニックネーム（ホームでは大きなロゴを本文に出すので、ナビバーのロゴは省く） | 画面下部のタブバー。4つのタブ（アイコン＋短い名前） |
| 項目 | ホーム・学習内容を選ぶ・知識マップ・設定 | ホーム・学習内容・知識マップ・設定 |
| 出さない画面 | 学習ルーム、ログイン・初回設定 | 学習ルーム、学習レポート、ログイン・初回設定 |

ナビを出さない画面では、ヘッダーのボタンで移動する。ホームのボタン（学習内容を選ぶ・知識マップ・設定）はナビと重なるが、そのまま置く。

## 3. ホーム

### 3.1 中身
ホームはロゴ・ぴあ友・ボタンだけのシンプルな画面にする（ADR-030）。
- **ロゴ**：「Piatomo」と、その下に「AIに教える学習アプリ」。
- **ぴあ友**：アバター（`idle`）と大きな吹き出し。吹き出しは`GET /sessions/?limit=1`のいちばん新しい授業から作る。
  - 授業がある：「前回は最後に〈小単元名〉を学習したよ！」（小単元名を大きく出す。複数あるときは最後の小単元）
  - 授業がまだない：「はじめまして！何を教えてくれるの？」
- **ボタン**：「学習内容を選ぶ」（大きく、いちばん目立たせる）、「知識マップ」、「設定」。
- ぴあ友の成長・最近の授業・次のおすすめは、ホームには置かない。成長は知識マップ、おすすめは学習内容選択で見られる。

### 3.2 PCとスマホの配置
| 要素 | PC | スマホ |
|---|---|---|
| 全体 | 中央寄せ。上にロゴ、下にぴあ友とボタンを横並び | 1列。上から順に縦に並べる |
| ロゴ | 上の中央に大きく | 上の中央 |
| ぴあ友と吹き出し | 左側。吹き出しを左、アバターを右に並べる | ロゴの下。アバターの上に吹き出し |
| ボタン | 右側に縦に3つ。「学習内容を選ぶ」が大きい | アバターの下。「学習内容を選ぶ」を横幅いっぱい、その下に「知識マップ」「設定」を横並び |

## 4. 学習内容選択

### 4.1 中身
- 校種・学年・教科（科目）で絞り込み、その下の単元→小単元の階層から選ぶ（ADR-031）。初めに開く校種と学年はプロフィールの値、教科は前回選んだもの（なければ数学）。高校は学年の代わりに科目で絞る。
- 画面の上に、PCは見出し「先生になって、ぴあ友に教えてあげよう！」、スマホはぴあ友の吹き出し（「前回は〈小単元名〉を学習したよ！」）とアバターを出す。
- 小単元は複数選択でき、上限は10。単元ごとに「まとめて選ぶ」で、その単元の小単元をすべて選べる。
- 各小単元に、ぴあ友の習得の状態（4状態）を出す。
- **おすすめ**は画面が計算する（ADR-023 A5）。次の3つをすべて満たす小単元に「おすすめ」の印を付け、プロフィールの学年に近い順に並べる。
  1. ユーザーの学年以下の小単元である
  2. その小単元の概念の前提（`GET /knowledge-graph/`の`prerequisite`）が、すべて練習中か習得済み
  3. その小単元の概念が、まだすべて習得済みにはなっていない
- 選んでいる小単元の一覧と、前提の確認（例：前提の「等式の性質」は、ぴあ友が習得済みです／前提の「分配法則」がまだ未習です）を出す。前提が足りなくても授業は始められる。
- 目安時間は表示しない（ADR-023 A5）。
- 非公開の小単元は表示しない（`GET /lessons/`は公開分だけを返す）。
- `/lessons/?select=<lesson_id>`で開いたときは、その小単元を選んだ状態にする（知識マップ、レポートから来たとき）。
- 「授業を始める」で`POST /sessions/`を呼び、作成された授業の学習ルームへ進む。失敗しても選択は残す。

### 4.2 PCとスマホの配置
| 要素 | PC | スマホ |
|---|---|---|
| 全体 | 中央に1列（最大幅 約1000px） | 1列 |
| 見出し・吹き出し | 上に見出し「先生になって、ぴあ友に教えてあげよう！」（吹き出しはなし） | 画面名「教える内容を選ぶ」の下に、吹き出し（左）とアバター（右） |
| 校種・学年・教科 | カードの上に横並び（校種は切り替え、学年・教科は選択。教科は青く塗って目立たせる） | カードの上に校種の切り替え。その下に「① 教科」（青）と「② 学年」を横並び |
| 単元→小単元の階層 | カードの中。小単元ごとにチェック、4状態、「おすすめ」 | カードの中（「③ 小単元」） |

## 5. 学習ルーム

### 5.1 PCとスマホの配置
PC は2列、スマホは1列。置くものは同じで、配置だけが違う。

| 要素 | PC | スマホ |
|---|---|---|
| 全体 | 左列約30%、右列約70% | 1列 |
| ヘッダー | 左にロゴ、教科・単元（下に小単元）。右に「授業を終える」 | 左に戻る、単元名（下に教科・学年／小単元）。右に「終える」 |
| アバター | 左列の上のカードに大きく。下に状態の一言 | 上のカードの左に小さく。右に状態の一言を吹き出しで |
| ぴあ友の理解度 | 左列の2つ目のカード。％とバー（5.6） | 上のカードの中。アバターの下に％とバー |
| ぴあ友の習得状況 | 左列の3つ目のカード（折りたためる）。概念ごとに名前と4状態。いま教えている概念は背景を青くし「いま教えている」の札と「習得まであと〇問」を付ける | 上のカードの下の折りたたみ。閉じているときは「ぴあ友の習得状況 1 / 3」（習得済みの数／概念の数）と、いま教えている概念の状態を1つ。開くと概念ごとの一覧 |
| 「教える／問題を出す」の切り替え | 右列の上、会話の右上にタブ | 画面の下、入力欄の下に大きなボタン2つ（選んでいる方を青く塗る） |
| 会話 | 右列の中央。ぴあ友の発言は左（小さなアバター付き、質問の種類の札）、ユーザーの発言は右の青い吹き出し。会話欄だけがスクロールする | 画面の中央。並びは同じ |
| 入力欄（教える） | 右列の下。文章入力と「送信」 | 画面の下に固定。文章入力と送信ボタン |
| 入力欄（問題を出す） | MathLiveの入力欄と「出題する」、数式の形式チェック、対応範囲（「一次方程式（文字1つ）」）、記号キー、入力例 | 同じ要素。入力例は省いてよい |

どちらの幅でも、入力欄と切り替えは常に見える位置に置き、会話をスクロールしても隠れないようにする。音声入力（マイク）は置かない（ADR-035）。

### 5.2 共通の動き
- **いま教えている概念**：直近のぴあ友の応答の`concept_id`。まだ応答がなければ、選んだ小単元の概念のうち、最初のまだ習得済みでない概念。習得状況のカードで強調し、「問題を出す」の対象にも使う。
- **送信中**：二重送信を防ぎ、ぴあ友を「考え中」にする。検証が終わる前に、DeepSeekの文章を少しずつ表示することはしない。
- **戻る**（スマホのヘッダー）：「授業を終える」と同じ確認を出す。授業を終えずに抜ける機能は置かない。PCのヘッダーのロゴも押せないようにする。
- **授業を終える**：確認のあと`POST /sessions/{id}/finish/`を呼び、学習レポートへ進む。

### 5.3 教える
- 自由記述で説明を送る。ぴあ友は根拠のある質問を1つずつ返す。
- ぴあ友の質問には、質問の種類の小さな札を付けてよい。「ヒントを見る」はMVPでは置かない（ADR-035）。札の文言は`action`から決める（`ask_why`＝理由をたずねる質問、`request_example`＝例をたずねる質問、`check_prerequisite`＝前提をたずねる質問、`contrast_cases`＝比べる質問）。
- 応答の`knowledge_changes`に変化があれば、会話の中に「〇〇：説明済み」などの小さな表示を出し、習得状況のカードも更新する。

### 5.4 問題を出す
「教える」とは**別の入力モード**。数式の形式チェックを通ってから`POST /sessions/{id}/exercises/`へ送る。

| 項目 | 仕様 |
|---|---|
| 対象の概念 | いま教えている概念（5.2）を`target_concept_id`に自動で入れる。ユーザーは選び直せる（ADR-023 A1） |
| 入力 | 一次方程式はMathLiveで入力し、`latex`と`question`を送る |
| 検証状態 | `VERIFIED`なら挑戦へ進む。`PROVISIONAL`は「練習としては使えるが、習得の回数には入らない」と表示。`UNSUPPORTED`は理由を出して入力し直してもらう |
| ぴあ友の解答 | `POST /exercises/{id}/attempt/`の`steps`を1行ずつ表示する。各行は式と、使った技能の名前（`skill_label`。例：両辺から同じ数をひく）（ADR-023 A2） |
| 待機中 | ぴあ友を「考え中」にし、入力欄とボタンを押せなくする |
| 解答のあと | `GET /peers/me/knowledge/`を取り直し、`required_correct`と`verified_correct`から「習得まであと〇問」を更新する |

解答の結果ごとの表示：

| 結果 | 画面の表示 |
|---|---|
| `correct` | 「検証済み・正解」。回数が増えたら「習得まであと〇問」 |
| `correct`＋`reason: duplicate_form` | 正解だが、前と同じ形の問題なので回数に入らないことを伝え、違う形の例（xが右辺にある、かっこがある など）を出す |
| `incorrect` | どの行で間違えたかを示す。ぴあ友の誤りを責める表現にしない |
| `blocked` | 止まった行に「ここで止まった」を出し、「まだ教わっていない技能：〇〇」（`blocked_skill`）と「教えるモードで説明する」ボタンを出す |
| `unverified` | 検証できなかったことを伝え、習得には使わない |
| 知識の変化で習得済みになった | 「ぴあ友が『〇〇』を習得しました！」の帯を会話に出し、アバターを`mastery_success`にする |

### 5.5 アバター
- SVG + Motion for React。状態と、アバターの下（スマホは横）に出す一言：

| 状態 | 一言の例 |
|---|---|
| `idle` | 待っています |
| `listening` | 聞いています |
| `thinking` | 考え中… |
| `question` | 教えてほしいことがあります |
| `practice_success` | できました！ |
| `mastery_success` | 「〇〇」を習得しました！ |

- 表情のアニメーションと知識の状態は分ける。`mastery_success`は、DRFが習得済みに更新したときだけ出す。
- 一度表示した成功アニメーションは、同じ応答を再受信しても再生しない。
- `prefers-reduced-motion`では動きを小さくし、同じ情報を色と文字・アイコンでも示す。
- アバターは、チームが生成AIで作ったロボットの画像を参考に、6つの状態の表情を描き分けたSVGで作る（ADR-036）。画像そのものはアプリに入れない。見た目は、白い丸い頭、紺色のバイザー（顔）、水色の目と口、青い耳、頭の上の小さなアンテナ。ほっぺは描かない。状態ごとの表情はデザイン08_avatar_statesのとおり（例：`question`は首をかしげて「？」、`mastery_success`は星の目と紙吹雪）。

### 5.6 ぴあ友の理解度
選んだ小単元の概念について、ぴあ友の状態を点にして平均し、％で出す（ADR-032）。画面が`GET /peers/me/knowledge/`から計算する。

| 状態 | 点 |
|---|---|
| 未習 | 0 |
| 説明済み | 1/3 |
| 練習中 | 2/3 |
| 習得済み | 1 |

例：概念が4つで、習得済み1・練習中1・説明済み1・未習1なら、(1 + 2/3 + 1/3 + 0) ÷ 4 = 50％。知識の状態が変わるたびに更新する。「理解度」は授業の進み具合の目安で、ぴあ友の習得の判定には使わない。

## 6. 知識マップ

### 6.1 中身
- 未習：点線の輪郭のみ、説明済み：淡く点灯、練習中：進捗の輪、習得済み：はっきり点灯。色だけでなくアイコンと文字でも区別する。
- 実線の矢印は前提関係（前提→後の概念）、破線は一般的な関連。凡例で意味を示す。
- 画面の見出しは「ぴあ友の知識マップ」。
- 選んでいるノードは黄色の枠で強調する。
- 表示範囲を切り替えられる：「学習中の単元」（直近の授業の小単元の概念と、その前提。小単元ごとに`GET /knowledge-graph/?lesson_id=`で取ってまとめる）／「〈学年〉〈教科〉ぜんぶ」。教科も選べる。
- ノードを押すと、詳細を出す：概念の説明（`ConceptNode.description`）、関係する小単元、前提、習得条件、検証済みの進み具合（例：1 / 2）。習得条件の文は画面が数値から作る（例：「異なる2つの形式で、検証済みの正答2問」）（ADR-023 A6）。
- 詳細の「この概念を教える」で、その概念を含む小単元を選んだ状態で学習内容選択を開く（`/lessons/?select=<lesson_id>`）。

### 6.2 PCとスマホの配置
| 要素 | PC | スマホ |
|---|---|---|
| 全体 | 左（広め）にマップ、右に詳細の2列 | 1列 |
| 表示範囲・教科の切り替え | 見出しの右に横並び（教科は青く塗る） | 見出しの下。表示範囲の切り替えを横幅いっぱい、その下に教科（青） |
| マップ | 左列。前提の概念を左、後の概念を右に並べる。ドラッグと拡大縮小ができる | 横幅いっぱい。前提の概念を上、後の概念を下に並べる。2本指で拡大縮小 |
| 凡例 | マップの下に1行 | マップの下に2行まで |
| ノードの詳細 | 右列に常に表示（未選択なら「ノードを選ぶと詳細が出ます」） | 下から出るシート。ノードを押すと開き、下にスワイプで閉じる |

## 7. 学習レポート

### 7.1 中身
- **あなたの授業は…**（説明力スコアのカード）：
  - ぴあとも独自の説明力スコア（100点満点）。点数を大きな青い数字で出し、赤い斜線と赤い「100」を添える（カラオケの採点のような見せ方）。「学校の成績ではありません」と添える。
  - 評価保留の観点が一部だけなら、残りの観点の配点で割り戻した合計を「〇点（評価保留の観点を除く）」と出す（[03](03_ai_learning_engine.md) G）。
  - すべて評価保留なら、点数は出さず「今回は点数を出せませんでした」と理由を出す。
  - 観点別の評価：**正確さ（40）・論理性（30）・分かりやすさ（30）**の3観点（ADR-015）。観点ごとに点数のバーか「評価保留」と、一言の説明（`explanation`）。ルーブリックの版は小さく出す。ぴあ友の質問への対応は独立の観点にしない。
  - ぴあ友のひとことを添える。APIからは受け取らず、画面が次の決まった文から選ぶ（上の行ほど優先）。〇〇には概念名が入る。

    | 条件 | ひとこと |
    |---|---|
    | 今回、習得済みになった概念がある | 「〇〇」を覚えました！ありがとうございます！ |
    | 今回、練習中になった概念がある | 「〇〇」の問題、もう少し練習したいです！ |
    | 3観点すべてが評価保留 | 今日はあまりお話しできませんでした。また教えてください！ |
    | 評価保留の観点がある | 〈保留の観点〉のところは、もっと聞いてみたかったです。 |
    | それ以外 | 今日もありがとうございました！また教えてください！ |

- **良かったところ**：APIの`strengths`（最大3件）を、チェックの印を付けて並べる（ADR-033）。0件ならこのカードは出さない。
- **ぴあ友がつまずいたところ**：端末に会話が残っていれば、ぴあ友が質問した発言を引用して並べ、「この発言を会話で見る（この端末のみ）」で会話へ移動できる。端末に残っていなければ出さない。サーバーは会話本文を返さない。
- **改善のヒント**：観点ごとの説明のうち、点数が70点未満の観点の説明を「改善のヒント」として出す。つまずいたところのカードの下にまとめる。
- **ぴあ友の習得**（見出しを分けた別のセクション）：
  - 今回の変化：`knowledge_changes`の前→後（ADR-023 A3）。
  - 次の学習の候補：`next_lesson_ids`の小単元。押すと、その小単元を選んだ状態で学習内容選択を開く。候補はサーバーが、公開中の小単元のうち、まだ習得済みになっていない概念を含むものを、①今回の授業の小単元、②前提がそろった別の小単元の順に最大3件選ぶ。
- ユーザー本人の推定習熟度は出さない（ADR-018）。
- ボタン：「もう一度教える」（同じ小単元で新しい授業を始める）、「学習内容を選び直す」。
- 評価がまだ終わっていない（`202`）間は「評価中…」を出し、数秒おきに取り直す。

## 8. 設定

### 8.1 中身
- **プロフィール**：ニックネーム・校種・学年の変更。「氏名・学校名・生年月日は登録しません」と添える。
- **会話とデータ**：「この端末に会話を保存する」の切り替え（初期値はオフ）と、「外部AIに送る情報」の説明。
- **ぴあ友の知識**：「リセットする」（スマホは「知識をリセットする」）。「習得状況がすべて未習に戻ります。過去の学習レポートは残ります」と説明する。
- **退会とデータ削除**：「退会する」と、リンク「データの保持期間について」。
- 知識リセットと退会は、確認の画面を出してから実行する。
- 「通知」の項目は置かない（ADR-021）。
- 画面のいちばん下に、アプリの版（例：Piatomo v0.1）を小さく出す。

## 9. ログイン・初回設定・同意
- 流れ：ログイン画面（「Googleでログイン」）→ 未登録なら、はじめての設定（プロフィールとデータの扱いの説明、同意のチェック）→「はじめる」でホームへ。同意のチェックがなければ「はじめる」は押せない。
- ログインはGoogleアカウントのみ（ADR-016）。
- 氏名、学校名、生年月日は尋ねない。ニックネーム、校種、学年だけ。
- 外部AIへ学習の文章を送ること、会話全文を原則サーバーに保存しないこと、保持期限を確認できるようにする。
- 一般公開で年齢に応じた保護者の同意が必要になる場合は、登録の流れに入れる（要法務確認）。
- 配置はPC・スマホとも中央に1列。PCは最大幅 約480px。

## 10. エラーと空の状態
どの画面も、次の状態を日本語で出す。

| 状態 | 出し方 |
|---|---|
| 読み込み中 | 骨組みの表示か「読み込み中…」。状態が分からないうちに「習得済み」などを出さない |
| データがない | 次にやることを出す（例：最初の授業を始めよう） |
| 通信の失敗 | 「通信できませんでした」と「もう一度」。入力した内容は消さない |
| ログインが切れた（401） | ログイン画面へ。戻ったら元の画面へ |
| 対応していない問題・評価保留・知識リセットの影響 | その場で理由と次にできることを出す |

## 11. アクセシビリティ・品質
WCAG 2.2 AAを努力目標とし、キーボード操作、適切なラベル、フォーカス表示、色に頼らない習得状態の表示、数式の読み上げ代替、文字サイズ調整、アニメーションの低減を備える。会話の自動スクロールは、ユーザーのスクロール位置を尊重する（いちばん下を見ているときだけ自動で下へ送る）。PC幅とスマホ幅の両方で、横スクロールが出ないことを確認する。
