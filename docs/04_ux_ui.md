# 画面・UX・コンポーネント仕様

**版** 1.1 / **改訂日** 2026-11-08 / **要求参照** FR-02〜08, NFR-03, PR-01

## 1. 全体方針
- PC・スマホ両対応のレスポンシブ。学習ルームはキャラクター＋チャット型（B案）で確定（ADR-017）。
- ユーザーは「学習内容選択→教える→ぴあ友からの質問→問題を出す→検証→レポート」を、少ない画面遷移で終えられる。
- 学校の正式な評価と混同させない。点数は**ぴあとも独自の説明力スコア**と明記する。
- 外見の比較ではなく、ぴあ友が「できるようになったこと」「習得した概念」を成長の主役にする。
- ぴあ友の習得は、用語集の4つの言葉（未習・説明済み・練習中・習得済み）とアイコンで表す。別の言い方はしない。

## 2. 画面一覧とルート
| 画面 | URL（静的ビルド対応） | 主な要素 | 使うAPI |
|---|---|---|---|
| ホーム | `/` | ぴあ友のSVGアバター、ぴあ友の習得状況、最近の授業、授業開始 | `GET /peers/me/`、`GET /peers/me/knowledge/`、`GET /sessions/?limit=` |
| 学習内容選択 | `/lessons/` | 校種・教科／科目、単元→小単元の階層、複数選択、おすすめ | `GET /lessons/`、`GET /peers/me/knowledge/`、`POST /sessions/` |
| 学習ルーム | `/study/?session=...` | アバター、会話、「教える／問題を出す」切り替え、MathLive入力 | `POST /sessions/{id}/messages/`、`POST /sessions/{id}/exercises/`、`POST /exercises/{id}/attempt/` |
| 学習レポート | `/report/?session=...` | 3観点の説明力スコア、評価保留、ぴあ友の習得の変化、次の学習の候補 | `POST /sessions/{id}/finish/`、`GET /sessions/{id}/evaluation/` |
| 知識マップ | `/knowledge/` | React Flow、前提関係、ノード詳細 | `GET /knowledge-graph/` |
| 設定 | `/settings/` | ニックネーム・学年、端末保存、知識リセット、退会 | `GET/PATCH /users/me/`、`POST /peers/me/knowledge/reset/`、`POST /users/me/deletion-requests/` |
| ログイン・初回設定 | `/`（未ログイン時） | Googleでログイン、ニックネーム・校種・学年、データ送信の説明 | `POST /onboarding/complete/` |

## 3. ホーム
- 「最近の授業」は`GET /sessions/?limit=3`の`SessionSummary`（小単元名、日時、説明力スコア）を新しい順に表示する（ADR-023 A4）。授業がまだなければ「最初の授業を始めよう」を出す。
- ぴあ友の習得状況は、4状態ごとの概念の数で示す。

## 4. 学習内容選択
- 校種→教科・科目→単元→小単元の順に絞り込む。小単元は複数選択でき、上限は10。
- **おすすめ**は画面が計算する（ADR-023 A5）。ユーザーの学年に合い、前提の概念がすべて練習中以上で、まだ習得済みでない小単元を優先する。
- 目安時間は表示しない。
- 非公開（`published: false`）の小単元は「準備中」として選べない状態で出す。

## 5. 学習ルーム

### 5.1 画面の区画
- PC：左側35〜40%にアバター・小単元・小さな進捗、右側60〜65%にチャットと入力。
- スマホ：上部にアバター（高さ控えめ）、進捗は折りたたみ、チャット中心。下部に「教える」「問題を出す」の切り替え。
- 送信中は二重送信を防ぎ、ぴあ友を「考え中」にする。検証が終わる前に、DeepSeekの文章を少しずつ表示することはしない。

### 5.2 教える
- 自由記述で説明を送る。ぴあ友は根拠のある質問を1つずつ返す。
- 応答の`knowledge_changes`に変化があれば、会話の中に「〇〇：説明済み」などの小さな表示を出す。

### 5.3 問題を出す
「教える」とは**別の入力モード**。数式の構文チェックを通ってから`POST /sessions/{id}/exercises/`へ送る。

| 項目 | 仕様 |
|---|---|
| 対象の概念 | いま教えている概念を`target_concept_id`に自動で入れる。ユーザーは選び直せる（ADR-023 A1） |
| 入力 | 一次方程式はMathLiveで入力し、`latex`と`question`を送る |
| 検証状態 | `VERIFIED`なら挑戦へ進む。`PROVISIONAL`は「練習としては使えるが、習得の回数には入らない」と表示。`UNSUPPORTED`は理由を出して入力し直してもらう |
| ぴあ友の解答 | `POST /exercises/{id}/attempt/`の`steps`を1行ずつ表示する。各行は式と、使った技能の名前（`skill_label`。例：両辺から同じ数をひく）（ADR-023 A2） |
| 待機中 | ぴあ友を「考え中」にし、ボタンを押せなくする |

解答の結果ごとの表示：

| 結果 | 画面の表示 |
|---|---|
| `correct` | 正解。習得の回数が増えたら「習得済みまであと〇問」 |
| `correct`＋`reason: duplicate_form` | 正解だが、前と同じ形の問題なので回数に入らないことを伝え、違う形の問題を促す |
| `incorrect` | どの行で間違えたかを示す。ぴあ友の誤りを責める表現にしない |
| `blocked` | 「〇〇がまだ分からない」と、`blocked_skill`の技能名を出す。その技能を教える方向へ誘う |
| `unverified` | 検証できなかったことを伝え、習得には使わない |

### 5.4 アバター
- SVG + Motion for React。状態：`idle`、`listening`、`thinking`、`question`、`practice_success`、`mastery_success`。
- 表情のアニメーションと知識の状態は分ける。`mastery_success`は、DRFが習得済みに更新したときだけ出す。
- 一度表示した成功アニメーションは、同じ応答を再受信しても再生しない。
- `prefers-reduced-motion`では動きを小さくし、同じ情報を色と文字・アイコンでも示す。

## 6. 知識マップ
- 未習：輪郭のみ、説明済み：淡く点灯、練習中：進捗の輪、習得済み：はっきり点灯。色だけでなくアイコンと文字でも区別する。
- 実線の矢印は前提関係、破線は一般的な関連。凡例で意味を示す。
- ノードを押すと、概念の説明（`ConceptNode.description`）、関係する小単元、前提、習得条件、検証済みの進捗を出す。習得条件の文は画面が数値から作る（例：「違う形の問題で3問正解」）（ADR-023 A6）。
- 学年・教科・いまの学習に関係する部分だけに絞り込めるようにし、概念が増えても見やすくする。

## 7. 学習レポート
- 上段：ぴあとも独自の説明力スコア（100点満点）。評価保留の観点がある場合は数値を断定しない。
- 中段：**正確さ（40）・論理性（30）・分かりやすさ（30）**の3観点（ADR-015）。観点ごとに点数か「評価保留」、説明、参照したルーブリックの版。ぴあ友の質問への対応は独立の観点にしない。
- 下段：ぴあ友の習得の変化（`knowledge_changes`の前→後）と、次の学習の候補（`next_lesson_ids`）（ADR-023 A3）。
- 「ぴあ友がつまずいたところ」は、端末に残っている会話から画面が拾って出す。サーバーは会話本文を返さない。
- ユーザーの説明力スコアと、ぴあ友の検証済みの習得は、見出しを分けた別のセクションにする。ユーザー本人の推定習熟度は出さない（ADR-018）。

## 8. 設定
- ニックネーム・学年の変更、端末保存（会話を端末に残すかどうか）、ぴあ友の知識リセット、退会。
- 「通知」の項目は置かない（ADR-021）。
- 知識リセットと退会は、影響の範囲を日本語で説明し、確認してから実行する。

## 9. ログイン・初回設定・同意
- ログインはGoogleアカウントのみ（ADR-016）。
- 氏名、学校名、生年月日は尋ねない。ニックネーム、校種、学年だけ。
- 外部AIへ学習の文章を送ること、会話全文を原則サーバーに保存しないこと、保持期限を確認できるようにする。
- 一般公開で年齢に応じた保護者の同意が必要になる場合は、登録の流れに入れる（要法務確認）。
- 通信の失敗、対応していない問題、評価保留、知識リセットの影響は、日本語で明示する。

## 10. アクセシビリティ・品質
WCAG 2.2 AAを努力目標とし、キーボード操作、適切なラベル、フォーカス表示、色に頼らない習得状態の表示、数式の読み上げ代替、文字サイズ調整、アニメーションの低減を備える。会話の自動スクロールは、ユーザーのスクロール位置を尊重する。
