# MVPの受入試験の記録（教材選択 → 説明 → 出題 → 検証 → 習得 → レポート）

MVPの一連の流れを通して、受入テスト（docs/06）の AT-03・04・05・10・12 を確かめた記録。
**結論：通しの試験は、まだ最後まで行えない。** 出題・検証・習得判定の API が、まだ `main` にないため、AT-04・05・12 は**未実施**（合格とは書かない）。AT-03 と AT-10 は、API で試験して合格した。画面の流れは、モックの上で確認できたが、これは画面の動きの確認で、習得判定の合格ではない。

| AT-04 | 検証済みの異なる形の 2 問で、標準の概念を習得 | API：出題の API がない | **未実施**（実装待ち） |

### AT-03（API）
- 試験：`apps/api/learning/test_acceptance.py` の `AT03_AiSaysUnderstood`。
- 期待：AI が「すごくよく分かりました！」と、成功の表情（`mastery_success`）つきで、6 回答えても、習得済みへの変化は 1 つもなく、DB に習得済み・習得した日時が入らず、画面に返る表情に `mastery_success` が出ない。出力の検証に通らない応答（`master_all`）は、定型の応答になり、知識は変わらない。
- 実測：期待どおり。

### AT-10（API）
- 試験：同 `AT10_RestartRestoresKnowledgeOnly`。
- 期待：説明を送って、授業を終え、新しいクライアント（同じ本人。ブラウザの会話がない状態）で取ると、知識（「移項」が説明済み）は取れる。授業の取得に、会話の本文は含まれない。会話の本文が、DB のどのテーブルにも残っていない。
- 実測：期待どおり。DB 全体の検索が、本当に文字を見つけられることも、わざと入れた文字で確認した（検索の道具が壊れていない）。

## 2. 手順ごとの確認（画面・モック）

教材選択 → セッション作成 → 説明 → ぴあ友の質問 → 出題 → 検証済みの解答 → 習得 → レポート → 知識マップ、を、実際のブラウザで通した。

| 手順 | 期待 | 実測 |
|---|---|---|
| 教材選択 | 小単元「方程式の解法」を選べる | 期待どおり |
| セッション作成 | 授業を始めると、学習ルームへ進む | 期待どおり |
| 説明 → 質問 | 説明を送ると、ぴあ友が質問を返す | 期待どおり（理由をたずねる質問） |
| 教えるだけ | 習得のお知らせも、成功の演出も出ない | 期待どおり |
| 出題 `x+3=7` | 検証済み・正解、「習得まであと 1 問」 | 期待どおり |
| 同じ形 `x+5=9` | 「前と同じ形」で、回数は増えない | 期待どおり（あと 1 問のまま） |
| 範囲外 `x^2=4` | 「対応していません」で、解答も回数も増えない | 期待どおり |
| 違う形 `2x+3=11` | 習得条件を満たして習得済み（お知らせは 1 件） | 期待どおり |
| 授業を終える | レポートに、説明力スコア・3 観点・習得の変化が出る | 期待どおり |
| 知識マップ | 「方程式の解法」が習得済みで出る | 期待どおり |

## 3. 環境と試験データ

- **API の試験**：すべての PR がマージされたあとの `main`（7bda887）。Django のテストの実行（`python manage.py test`）。DB は SQLite のテスト用 DB（CI では PostgreSQL）。**外部の AI（DeepSeek）はモック**。受入試験を足して、全体で 150 件が成功（skip 4 件は、未実装の項目）。
- **画面の確認**：ヘッドレス Google Chrome 153、幅 1280×900、開発サーバー、**API はモック**（実際の API ではない）。すべての PR がマージされたあとの `main`（7bda887）で、2026-11-14 に取り直した（11 項目すべて期待どおり）。
- **試験データ**：テスト用の利用者（`uid-accept`）と、試験用に作った仮の教材（等式の性質・方程式の解法・移項。`lessons/test_api.py` の `make_tree`）。**検証済みの正式な教材データは、使っていない**（まだ投入していない）。
- 自動試験は、何度でも再現できる。画面の確認は、この文書の手順どおりに、手で再現できる（確認に使った自動スクリプトは、この変更には含めていない）。

## 4. 未達・できていないこと（完了扱いにしない）

1. **出題・検証・習得判定の API が、`main` にない**（出題の受付、ぴあ友の解答、習得条件の判定）。このため、AT-04・05・12 を、本物のシステムで試せない。実装後に、`test_acceptance.py` の `NotYetImplemented` の skip を外して、試験を書く。
2. **画面は、モックにしかつないでいない。** 画面と本物の API の結合は、確認していない。
3. **画面での再起動後の復元（AT-10 の画面側）は、確認できていない。** サーバー側の復元（API）だけ、確認した。
4. **正式な教材データ（検証済みの小単元）で試していない。**
5. **外部の AI（DeepSeek・Jev）は、実際につないでいない**（モック）。AI の実際の出力の質・応答時間・失敗時の動きは、確認していない。
6. 設定の画面がない（ナビの「設定」は 404）。ログアウトの置き場所も未定。
7. スマホの実機・他のブラウザ・スクリーンリーダーでの通しは、していない。

この試験の範囲では、見つかった不具合は、なし。ただし、上の未達の項目は、試験していないので、「不具合がない」とは言えない。

## 6. 再現の手順

- API：`cd apps/api && source .venv/bin/activate && python manage.py test learning.test_acceptance -v 2`（合格 5 件、skip 3 件が出る）。
- 画面（モック）：`apps/web` で `npm run dev`（`NEXT_PUBLIC_API_MOCK` を設定しない）。`/lessons/` で「方程式の解法」を選んで授業を始め、説明を 3 回送り、「問題を出す」で `x+3=7`、`x+5=9`、`x^2=4`、`2x+3=11` を順に出題し、「授業を終える」でレポートを見て、知識マップで状態を確かめる。
