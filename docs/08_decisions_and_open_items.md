## 2. 技術・法務・費用面の未検証事項
| 項目 | 閉じるための条件 |
|---|---|
| 本番PostgreSQLの提供方法 | Cloud SQL等の実際の価格と接続制限、無料枠、DBリージョン確認 |
| DeepSeek API | 利用規約・個人情報の保持・送信先・未成年向け可否の現行確認 |
| Jev API | 購入・実接続・日本語採点品質・利用条件の実測 |
| 国研ルーブリック | 各公開小単元の対応ページ・評価規準を人がレビュー |
| 退会後完全削除 | Cloud SQL backups/Cloud Logging/第三者委託先ごとの保持ルール実地確認 |
| 未成年同意 | 運営形態・実利用年齢・第三者送信を踏まえ法務確認 |
| Skill Executor | 安全な式パーサー、解法パターン、解法証明の実装・負荷テスト |
| 教材の中身 | 公開する3つの小単元（ADR-028）の定義・例題・解法ルール・習得条件を作り、人が確認する（#14・#17） |
| 説明力スコアの配点 | 40・30・30は仮の値。採点の比較実験（#67）の結果で見直す |
| ホームのロボット画像 | ChatGPTで作成。OpenAIの利用規約（2026-01-01版）では、出力の権利は作った人に譲渡され、クレジットの表記は求められていない。ただし、出力は他の人と似ることがあり、AIが作ったものを人が作ったと表示してはいけない。残りの確認：作った人のアカウントで作ったこと、既存のキャラクターに似ていないこと、作った日とプロンプトの記録を残すこと（ADR-038） |

## 3. 仕様変更ルール
- 要件ID→OpenAPI契約→DBモデル→実装→テスト→説明資料の順に影響を確認する。
- `00_master_spec.md`を正本とし、他文書は詳細を担当する。用語は[用語集](glossary.md)に従う。
- 未実装でもAPI契約だけは変更履歴を残して同期する。
- 変更はPRで行い、この文書の表に決定を1行追加する。
