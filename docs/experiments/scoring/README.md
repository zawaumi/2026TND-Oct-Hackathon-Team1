# 採点実験のデータと人手基準

DeepSeek・Jev による説明の採点を、**人の採点と比べる予備実験**（docs/06 の C、docs/03 の H）のためのデータと手順。
**小規模な予備実験**で、優位性を前提にしない。差が出なかった場合も報告する。

**状態：採点以外の準備は、完了。2名の独立採点・不一致の協議・比較基準の確定は、まだ行っていない**（下の「結果の記録」は空欄）。

## 採点する人へ（まず、ここだけ読む）

1. **`score_tool.html` を、ダブルクリックで開く**（Google Chrome がおすすめ。インターネットは要らない）。
2. 名前（A・B など）を入れて、「AIを使わずに、自分ひとりで採点します」にチェックを入れ、セットを選んで、採点を始める。
3. 会話を読んで、3つの観点を、それぞれ 1〜5 で選ぶ。判断する根拠が、会話にないときだけ、「評価保留」にして、理由を書く。点は、自動で保存される（ブラウザを閉じても、同じパソコンの同じブラウザなら、続きから再開できる）。
4. 終わったら、「CSVに保存」を押す。できた `rater_名前_セット名.csv` を、集める人に渡す。
5. **もうひとりの採点者と、相談しない。AI を使わない。`answer_key.json`（キー）を開かない。**

セットは3つ：調整用（9件・約25分）→ 協議 → 評価用（36件・約1.5〜2時間）。誘導（12件）は任意（目安の時間は、作成者の見積もりで、実測ではない）。

## 中身

| ファイル | 内容 |
|---|---|
| `score_tool.html` | 採点ツール（1つのファイルで動く。通信しない） |
| `conversations.json` | 架空の会話45件（説明・ぴあ友の質問・その答え）。種類（正しい・不完全・誤り）は書かない |
| `split.json` | 調整用9件・評価用36件の分け方（固定の記録） |
| `induced.json` | 採点誘導12ペア（元の会話と、誘導の文を足した会話の対応） |
| `score_sheet_*.csv` | 採点シート（空欄）。ツールを使わずに、表計算ソフトで採点するとき用 |
| `frozen_manifest.json` | 固定したデータの指紋（SHA-256）。変えると、`check_data.py` が失敗する |
| `check_data.py` | データの整合の検査（件数・分割・ペア・個人情報・指紋・ツールとの一致） |
| `analyze_scores.py` | 2名の採点を集計し、不一致の一覧（協議の資料）を作る |
| `finalize_baseline.py` | 協議の結果から、比較基準を作って固定する |
| `answer_key.json` | 各会話の種類・意図した欠点。**採点が終わるまで、ここに入れない**（下記） |

## データの分け方（固定）

- 会話45件：**正しい15・不完全15・誤り15**。小単元（等式の性質・方程式の解法・移項）ごとに、各種類5件。
- **調整用9件**：規準の読み方をそろえるために使う（各種類3件、小単元ごとに1件）。**本評価から除く。**
- **評価用36件**：ロックして、DeepSeek・Jev との比較に使う（各種類12件）。**調整に使わない。**
- **採点誘導12ペア**：評価用の会話から、種類ごとに4件を選び、元の文に、採点を誘導する文を足したものを対にした（採点者への指示・役割のなりすまし・偽の評価の結果・感情への訴え、が各3件）。誘導の文以外は、元と同じ。
- 会話のIDは、固定の乱数でふってあり、IDから種類や小単元は分からない。

## 会話の形

各会話は、`lesson`（小単元）、`teacher_explanation`（ユーザーの説明）、`peer_question`（ぴあ友の質問）、`teacher_answer`（質問へのユーザーの答え）。Jev に渡す `state`（docs/03 の F）と同じ項目。
質問への対応は、独立した観点にせず、**3観点それぞれの中で**評価する（正確さ：答えに誤りがないか／論理性：根拠を示して答えたか／分かりやすさ：つまずきを言い換えや例で補えたか）。

## 採点の規準（版：`draft-2026-11`）

配点は仮の値（正確さ40・論理性30・分かりやすさ30。ADR-015）。各観点を1〜5の段階で採点する。文は `apps/api/evaluations/defaults.py` と同じ。

| 段階 | 正確さ（40） | 論理性（30） | 分かりやすさ（30） |
|---|---|---|---|
| 1 | 重大な誤りがある | 手順も理由も示されていない | つまずきに応えていない |
| 2 | 重要な条件が複数欠ける | 手順だけで理由がない | 同じ説明を繰り返している |
| 3 | 一部は正しいが条件が不十分 | 理由はあるが飛躍がある | 言い換えか例のどちらかがある |
| 4 | 概ね正しい | 概ね筋道が通っている | 言い換えや例で概ね伝わる |
| 5 | 数学的に正確で必要な条件がある | 手順と理由がつながり、質問にも根拠を示して答えている | 具体例と言い換えで、つまずきを解消している |

- 点数への換算：段階1〜5を、20・40・60・80・100点とし（ADR-029）、配点で重み付けして合計する。
- **評価保留**：その観点を判断する根拠が、会話にないときだけ。評価保留の観点は、合計から除き、残りの配点で割り戻す。会話の量や長さだけで、採点しない。

## 採点のルール（独立採点）

1. 採点するのは**2名**。**互いの結果を見ない**。相談しない。
   **採点は、人が自分で行う。** AI（Claude・ChatGPT など）に採点させたり、AIの採点結果を見たりしない（「人の基準」を作る実験なので、AIが関わると意味がなくなる）。ツールでは、採点を始めるときに、宣言のチェックが要る（CSVに記録される）。
2. 採点が終わるまで、**`answer_key.json` を開かない**（種類を知ってから採点すると、偏る）。
3. 各会話の3つの文を、すべて読んでから、3観点それぞれを1〜5で採点する。

## 手順

1. **調整用9件**を、2名が独立に採点する。
2. 結果を見せ合い、**規準の読み方の違いを協議**して、「規準の補足」に記録する（規準の版 `draft-2026-11` の文は変えない。補足は、別に記録する）。
3. **評価用36件**を、2名が独立に採点する（補足を適用する）。
4. 集計して、不一致の一覧を作る：

   ```
   python3 docs/experiments/scoring/analyze_scores.py --set evaluation rater_A_evaluation.csv rater_B_evaluation.csv --out results
   ```

   一致の度合い（`agreement_evaluation.md`：一致率・MAE・重み付きκ・Spearman）と、協議する行（`disagreements_evaluation.csv`）ができる。
   段階が違うものは、既定ですべて協議する（`--threshold 2` なら、差が2以上だけ。差が小さいものは、平均にする）。**「不一致」の基準は、2名で決めて、記録する。**
5. 2名で、`disagreements_evaluation.csv` の「協議後の基準」（1〜5、または UNRATED）と「理由」を、すべて埋める。
6. 比較基準を作って固定する（埋まっていないと、止まる。AIが基準を決めることは、できない）：

   ```
   python3 docs/experiments/scoring/finalize_baseline.py --set evaluation rater_A_evaluation.csv rater_B_evaluation.csv results/disagreements_evaluation.csv --out results
   ```

   `baseline_evaluation.json`（版・採点者・入力の指紋・観点ごとの基準）ができる。
7. 誘導のシート（12件）は**任意**：誘導の文を足しても、人の点が変わらないことの確認用。省いた場合は、記録に書く。
8. 確定したら、`answer_key.json` を、このフォルダに入れる（下のSHA-256と同じことを確かめる）。`check_data.py --key answer_key.json` で検査する。

## データの出どころと限界（必ず読む）

- 会話はすべて**架空**で、実在の人・学校・個人情報を含まない（`check_data.py` で、メール・URL・電話番号らしい数字・学校名らしい語がないことを確かめている。目安の検査で、完全ではない）。
- **会話は、AI（Claude）が書いた。** ぴあ友の質問も、実際の DeepSeek の出力ではなく、書いたものである。AIの文体が、採点するAI（DeepSeek・Jev）に有利・不利に働く可能性がある（循環）。結果を読むときの限界として、発表でも明記する。
- 計算の主張（例：「x＋3＝7 の解は4」）は、機械で検算した（40件。正しい・不完全の会話に誤りはなく、誤りの会話の「誤った解」は、実際に誤り）。**概念の誤り（例：「右辺だけに3をたす」）の判定は、検算していない。** 種類（正しい・不完全・誤り）は、作成者の意図で、人の採点結果ではない。人の採点が、これと食い違うことも、データになる。
- 集計の道具（重み付きκ・Spearman）は、scikit-learn・scipy の結果と、ランダムな200組で照合した（差は 1e-15 未満）。
- 件数が少ない（45件）ので、**統計的に優位性や教育効果を証明できない。**
- 教材は、中1数学の3つの小単元だけ。
