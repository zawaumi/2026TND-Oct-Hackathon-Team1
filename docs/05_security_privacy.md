# セキュリティ・プライバシー・削除運用仕様

**版** 1.1 / **改訂日** 2026-11-08 / **要求参照** SEC-01〜03, PR-01〜02

## 1. 脅威モデル
保護対象：認証済みUID、最小プロフィール、ぴあ友の共通知識グラフ、検証済み演習・評価、APIキー、DB資格情報。攻撃者：未認証第三者、他ユーザー、入力フィールドを操作する本人、改ざんされたブラウザ履歴、外部AI出力、外部依存の侵害を想定。

## 2. 権限と認証
- ログインはGoogleアカウントのみ（ADR-016）。Firebaseの匿名認証やメール・パスワード認証は有効にしない。
- Firebase ID tokenをサーバー側Admin SDKで検証。必要に応じて`check_revoked=True`で失効を照合。検証不能は許可しない。
- APIはデフォルト`IsAuthenticated`。管理・公開教材を除くリソースは`owner=request.user`で絞る。
- 初回ユーザー作成は登録と同意の完了APIだけで実行する。GETで黙示的にアカウントを新規作成しない。
- OpenAPIで`firebaseBearer`を宣言。外部AIサービス向けキーはブラウザへ露出しない。
- 送信頻度とトークン費用はユーザー単位のレート制限・予算上限で抑制。CORSは認証の代用ではない。

## 3. 入力検査レイヤー
| 段階 | 検証例 | 結果 |
|---|---|---|
| Schema | body型、文字数上限、UUID、LaTeX構文 | 無効→400/422 |
| 正規化した検知用テキスト | 役割偽装、採点命令、MASTERED一括指示、秘密情報要求 | シグナルを付与 |
| 内容判定 | 授業中に引用された攻撃文 vs 実際の操作命令 | ALLOW / DATA_ONLY / REJECT |
| 送信内容最小化 | UID、メール、ID tokenの除外、PIIマスキング | 必要情報のみ外部AIへ |
| LLM出力 | Schema, action enum, concept scope, skill許可, 数式ステップ | 不正→固定フォールバック |
| DB確定 | トランザクションと版、所有者、証拠の検証 | 矛盾→状態を更新しない |

### 注意
キーワードフィルタは回避・誤検知がある。指示を「データ」として隔離する設計も万能ではない。**実際に学習状態・点数を変更する機能はDRFの明示的なAPI操作に限定し、AIが生で書いた命令を実行しない**ことが本体防御。

## 4. Outputの信頼性
`used_skills`をモデルが自己申告しても真実とは限らない。式変形は決定的なステップをサーバーで検証。自然文の完全な意味検証は不可能なので、技能が厳密に制限される算数・数学では定型質問と検証済みステップの組み合わせを使う。プロンプト漏洩要求は応答しない。

## 5. データの保持と第三者送信
- 会話全文：サーバーDBへ永続保存しない。ブラウザメモリ内で扱い、IndexedDBへの保存はユーザーの明示選択。
- 検証根拠：概念、問題形式、正誤、使用可能な技能と検証済みのステップ種別。生本文は原則保存しない。
- 評価結果：スコア・ルーブリック版・評価モデル名と状態のみを保持。根拠の長文引用は端末でのみ表示。
- DeepSeek/Jevには教材の必要箇所と直近入力のみを転送。これは第三者送信なので、利用者への説明と契約確認が必須。
- デバッグログ：本文・トークン・認証ヘッダ・Googleプロフィールを記録しない。

## 6. 退会 / データ削除
1. 認証済み本人が意図を確認して退会申請（必要に応じ再認証）。
2. すぐに`account_status=deleting`にしてアクセスを遮断。リトライ可能なDeletionRequestジョブを記録。
3. PostgreSQLの本人に紐づくPeer、Knowledge、Session、Evaluation、私有教材等を削除。Firebase Authアカウントも削除。
4. 成功と失敗を最小限の監査記録に残し、失敗した工程だけ再実行。外部システム間の単一トランザクションを仮定しない。
5. バックアップが復元された場合に削除済みアカウントを再削除できるように、復元手順へ削除台帳との照合を組み込む。
6. 削除追跡情報自体にも短い保持期限を設ける。

**暫定SLO（一般公開前に実測・クラウド設定を確認）**：アクセス即時停止、稼働DB+Firebase Auth 24時間以内、アプリ通常ログ7日以内、バックアップ最大30日以内。Cloud SQL手動バックアップは無期限保持になり得るので作成・監査・削除ルールが必須。Google Cloudの一部必須監査ログ（`_Required`）は400日固定であり「全コピーが30日以内に消える」と約束しない。外部AI事業者の保持は要調査。

## 7. CI/運用上の監査
- `.env*`、サービスアカウントJSON、AI鍵、実データのコミット禁止。Secret scanningを有効化。
- 本番向け設定で`DEBUG=False`、`ALLOWED_HOSTS`、HTTPS、セキュアヘッダ、CORS origin制限、管理画面保護。
- 本番依存ライブラリの脆弱性監査、依存更新、ブランチ保護とPRレビュー。
- 退会処理・バックアップ削除、外部AI送信内容、入出力検証の監査証拠を残す。ただし本人の文章内容は記録しない。
