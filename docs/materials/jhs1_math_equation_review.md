| ex-word-1 | 方程式を使った文章題 | `word-problem` | `（自動採点しない参考例）` | 110 |

検算の内容（`lessons/curated.py`）：
1. 式を安全な文法（一次式・整数と有理数）だけで読む。`eval` は使わない。
2. 書いてある解が、実際の解と一致し、元の式に代入して左右が等しい。
3. 各ステップが、書いてある規則（たす・ひく・かける・0以外でわる）を両辺に使った結果と一致する。0でわる・片辺だけの操作・符号の変え忘れは検出される。
4. 使った技能が、その概念か前提の概念の技能に入っている。
5. 最後のステップが `x=（数）` の形。
6. 概念の前提に循環がない。習得条件を、例題の数・形の種類で満たせる。
7. 公開する小単元が、ADR-028 の3つだけ。文章題の小単元（検証できない概念）は公開できない。

## 6. 未決・要確認

1. **定義・学習目標・例題の保存先。** 現在の DB には、小単元の定義や例題を入れる項目がない（`Lesson` に説明の欄がなく、`Exercise` は今後追加予定）。いまは、概念の説明（1〜2文）だけが DB に入り、API（`GET /knowledge-graph/`）で取れる。定義・学習目標・例題・採点規準はデータファイルで版管理している。DB や API で取るには、項目の追加が要る（API 契約にも影響する）。方針の決定が必要。
2. **移項を独立した技能にするか。** いまは、移項を「等式の性質（たす・ひく）を短く書いたもの」として、新しい規則名を作っていない。Skill Executor が、移項の知識の有無を区別する必要があるなら、規則名の追加が要る。
3. **「同じ数」か「同じ数や式」か。** x の項の移項（例 `2x=x+5`）では、両辺から `x` をひく。概念の説明は「同じ数や式」としたが、MVP の文法で、文字を含む式を引数にしてよいかを確認したい。
4. **前提関係の入れ方。** 移項の前提は「等式の両辺に同じ数をたす・ひく」だけにした。移項の例題が、わり算を使わず、たし算・ひき算だけで解けるようにしてある。解法の前提は、たす・ひく／かける・わる。
5. **習得条件・配点は仮。** 採点の比較実験や運用データで見直す。
6. **小数・分数・かっこを含む方程式は、MVP の例題に入れていない**（`distribute` は文字式の単元の技能）。入れるかは、数式の文法と Skill Executor の対応範囲に合わせて決める。
7. **公式資料の引用の扱い。** 本文は転載しておらず、式は独自。NIER・文部科学省の資料の利用条件は、法務の確認の対象に含めるか確認する。
8. **モックとの違い。** `apps/web` のモックデータ（概念ID 101-103、`M1-EQ-*` のコード）は、この教材の概念コードとは別物。実際のAPIでは、DBが採番したIDが返る。

## 7. 投入の手順（開発DB）

```sh
cd apps/api
source .venv/bin/activate
python manage.py migrate
python manage.py load_curated_lessons --check      # 検査だけ（DBは触らない）
python manage.py load_curated_lessons              # 下書きとして投入（公開しない）
python manage.py shell -c "from lessons.models import *; print(Lesson.objects.values_list('title','status'))"
```

- 何度実行しても、重複して作られない。公開済みの教材を、このコマンドが下書きに戻すことはない。
- 画面（`apps/web`）で試すためだけに公開したいときは、`DEBUG=True` の開発環境で `--publish --allow-unreviewed` を付ける（本番では使えない）。
- レビュー承認後は `--publish` で、MVP の3小単元（と、その領域・単元）が公開される。文章題の小単元は公開されない。
- 前提関係と習得条件のモデルができたら、同じコマンドを再実行すると投入される（前提関係は、モデルがあれば自動で入る）。
