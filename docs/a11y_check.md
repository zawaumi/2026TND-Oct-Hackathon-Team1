# レスポンシブとアクセシビリティの確認記録

主要画面を、PC幅とスマホ幅で、キーボード・フォーカス・読み上げ・色・動きの面から確認した記録。画面の配置は docs/04、色と書体は docs/04 の 1.3 に従う。

## 対象の画面

ホーム／ログイン（ログインが切れたとき）／初回設定／学習内容選択／学習ルーム（教える・問題を出す）／知識マップ（地図・ノードの詳細）／学習レポート／設定。
**設定の画面は、まだない**（`/settings/` のページがなく、ナビのリンク先は 404 になる）。確認できていない。

## 環境と方法

- ブラウザ：ヘッドレス Google Chrome 153（`@sparticuz/chromium`、`puppeteer-core`）。開発サーバー（`npm run dev`）、**API はモック**（実際の API ではない）。
- 画面の幅：PC 1280×860、スマホ 390×844（タッチあり）。
- 自動検査：axe-core 4.14.0（WCAG 2.0・2.1・2.2 の A・AA）、横スクロールの有無、操作部品が他の要素に覆われていないか（`elementFromPoint`）、操作部品の大きさ（24px 未満）、Tab で移動したときのフォーカスの印。
- 手で操作して確認：キーボードだけの一連の操作（ログイン → 小単元の選択 → 授業を始める → 説明の入力）、モーダルのフォーカス、`prefers-reduced-motion`、数式入力。
- 開発サーバー特有の表示（右下の Next.js の丸いバッジ）は、本番にないので、結果から除いた。

## 確認できたこと（問題なし）

- **横スクロール**：全画面・両方の幅で、なし。入力欄・タブバー・固定の部品が、他の操作部品を覆っていない（モーダルの背景を除く）。
- **キーボード**：ログイン → 小単元の選択（スペース）→ 授業を始める → 説明の入力 → 送信まで、すべて Tab で届き、フォーカスの印が見える。
- **授業を終える確認**（ブラウザ標準の `<dialog>`）：開くと「続ける」にフォーカスが入り、背景は操作できず、Esc で閉じて、元の「終える」にフォーカスが戻る。
- **色以外での区別**：知識の4状態は、文字（未習・説明済み・練習中・習得済み）と、形の違うアイコンで区別する。辺の向きは、矢印と、読み上げ用の名前で示す。
- **動きを減らす設定**：アバターは止まった絵になり、繰り返しの動きはなくなる。頭の傾き・「？」・点・星・紙吹雪の絵と、下の一言（文字）で、状態が分かる。
- **数式入力**：入力欄に名前（「問題の式を入力（数式の入力欄）」）、記号キーに名前（たす・ひく・かける・わる・イコール・分数・かっこ）、入力した式の読み上げ用の言葉、文字入力への切り替えがある。
- 全画面で `html lang="ja"`、見出し（h1）がある。

## 未対応・要判断

1. **青地の白い文字のコントラスト不足（4.17:1。AA の基準は 4.5:1）。** ボタン（学習内容を選ぶ・授業を始める・出題する・もう一度教える など）、範囲の切り替え、教科の選択で出る。デザインの値（メインの色 `#4677E6`）によるもの。
   **提案：** `src/app/globals.css` の `--color-primary` を `#4270dd` に変える（白い文字とのコントラストが 4.57:1。見た目はほとんど変わらない）。確認用に変えて検査したところ、**全画面で axe の違反がなくなった**。採用するなら、docs/04 の 1.3 の色の表も直す。デザインの決定なので、この記録の PR では変えていない。
2. **設定の画面がない**（上記）。画面ができたら、同じ確認をする。
3. **実機・他のブラウザ・スクリーンリーダー**：実機（iOS・Android）、Safari・Firefox、実際のスクリーンリーダー（VoiceOver・TalkBack・NVDA）での確認は、していない。読み上げの名前は、ブラウザのアクセシビリティツリーで確認した。
4. **知識マップのキーボード操作**：ノードは Tab で移動し、Enter・Space で選び、Esc で外せる。地図の移動・拡大縮小は、画面の「＋」「－」「全体表示」ボタン（Tab で届く）で行う。矢印キーでの地図の移動は対応していない。
5. **数式入力の読み上げ**：MathLive の中の読み上げ（数式を声にする機能）は、実際の読み上げソフトでは確認していない。代わりに、入力した式の読み上げ用の言葉を、入力欄の下に用意した。
6. **フォーカスの印の自動検査**：数式の入力欄は、枠（外側の `div`）にフォーカスの輪が出る作りで、自動検査では「見つからない」と出るが、画面で輪が出ることを目で確認した。
7. **WCAG 2.2 AA は努力目標**。この確認は網羅的な監査ではない。
