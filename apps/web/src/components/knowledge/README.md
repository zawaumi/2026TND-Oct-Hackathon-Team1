# 知識マップ（/knowledge/）

ぴあ友の知識を、React Flow で、前提の関係と4つの状態つきで出す画面（docs/04 の 6）。

## 表示するもの
- 見出し「ぴあ友の知識マップ」。範囲の切り替え（「学習中の単元」／「中1数学ぜんぶ」など）、教科、「最新にする」。
- 地図：概念をノードにして、前提の関係を矢印で結ぶ。PC は前提が左・あとの概念が右、スマホは前提が上・あとの概念が下。ドラッグで動かし、拡大縮小もできる。
- 凡例：4つの状態の印と、辺の意味。選んだノードは黄色の枠。
- ノードの詳細：概念の説明、関係する小単元、前提、習得条件、検証済みの進み具合、「この概念を教える」（`/lessons/?select=<小単元のid>`）。PC は右の列に常に出し、スマホは下から出るシートにする（下に引く・「閉じる」・外側を押す・Esc で閉じる）。

## データ
- `GET /knowledge-graph/`（概念と辺）と `GET /peers/me/knowledge/`（本人の知識状態）、`GET /lessons/`（関係する小単元）、`GET /sessions/?limit=1`（直近の授業）を取る。
- **状態**は、本人の知識状態（`/peers/me/knowledge/`）を優先し、そこにない概念はグラフのノードの値を使う（`resolveStatus`）。
- **辺**は、`source`（前提の概念）→ `target`（あとの概念）。`relation` が `prerequisite` なら実線の矢印、`related` なら破線（矢印なし）。
- **「学習中の単元」**は、直近の授業の小単元ごとに `GET /knowledge-graph/?lesson_id=` で取って、まとめる。授業がなければ、最初から「ぜんぶ」を出す。
- 他の人の私有の概念を出さないことは、API が担う（この画面は、API が返した概念だけを出す）。
- 開いたとき・「最新にする」を押したとき・タブに戻ったときに取り直す。取り直しに失敗しても、前に取った内容は残し、失敗したことを出す。

## 習得条件の文
画面が API の数値から作る（`src/lib/knowledgeMap.ts` の `masteryCondition`）。保存した文は使わない。API は必要な正答数（`required_correct`）だけを返し、「異なる○つの形式」の数は返さないので、いまは「検証済みの正答○問」と、同じ形の問題はくり返しても数えないことだけを書く。形式の数まで書くには、API の契約に形式数を足す必要がある。

## 色以外でも分かるように
4つの状態は、文字（未習・説明済み・練習中・習得済み）と形の違うアイコン（点線の輪・淡い点灯・進捗の輪・チェック）でも区別する。辺の向きは矢印と、読み上げ用の名前（「前提：A から B へ」）で示す。地図が見えなくても、読み上げ用の一覧で、概念・状態・前提が分かる。ノードは Tab で移動し、Enter／Space で選び、Esc で外せる。

## 確認のしかた（モック）
`npm run dev`（`NEXT_PUBLIC_API_MOCK` を設定しない）で `/knowledge/` を開く。モックには、習得済み・説明済み・練習中・未習の4つの概念と、前提の矢印がある。`?mock=networkError` で、通信失敗の表示と「もう一度」を確かめられる。`npm run test:knowledge` で、レイアウトと習得条件の文などを確かめられる。
